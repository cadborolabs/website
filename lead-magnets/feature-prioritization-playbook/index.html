The Six Frameworks, Explained

RICE
Most Popular
Reach × Impact × Confidence / Effort
Formula
RICE = (Reach × Impact × Confidence%) / Effort

Use when

  • You have reach/usage data
  • Need defensible, quantitative ranking
  • Comparing 10+ features objectively

Avoid when

  • No reliable reach estimates
  • Prioritizing quick experiments
  • Team resists scoring overhead
Example

"Add CSV export" — Reach: 2,000 users/q, Impact: 2 (high), Confidence: 80%, Effort: 3 person-weeks
RICE = (2000 × 2 × 0.8) / 3 = 1,067

ICE
Fastest
Impact × Confidence × Ease
Formula
ICE = Impact (1–10) × Confidence (1–10) × Ease (1–10)

Use when

  • Running growth experiments
  • Need a score in 2 minutes
  • Small team, rapid iteration

Avoid when

  • Scores need to survive exec scrutiny
  • Comparing very different initiatives
  • Need auditability
Example

"Test new onboarding flow" — Impact: 8, Confidence: 6, Ease: 7
ICE = 8 × 6 × 7 = 336

MoSCoW
Best for Alignment
Must / Should / Could / Won't
How it works
Sort every item into one of 4 buckets:
Must have → Should have → Could have → Won't have

Use when

  • Scoping a release or MVP
  • Need stakeholder consensus fast
  • Binary "in or out" decisions

Avoid when

  • Need to rank-order within a tier
  • Everything gets labeled "Must"
  • Comparing effort trade-offs
Example — MVP release scoping

Must: User auth, core workflow, billing
Should: Onboarding wizard, email notifications
Could: Dark mode, CSV export
Won't: Mobile app, AI features (v2)

WSJF
Enterprise / SAFe
Weighted Shortest Job First
Formula
WSJF = Cost of Delay / Job Duration
CoD = User-business value + Time criticality + Risk reduction / Opportunity enablement

Use when

  • Enterprise / SAFe environment
  • PI planning with multiple teams
  • Time sensitivity matters (deadlines, market windows)

Avoid when

  • Small team, no PI cadence
  • Can't estimate job duration reliably
  • Stakeholders unfamiliar with SAFe
Example

"Compliance feature for EU launch" — User value: 8, Time criticality: 13, Risk reduction: 8, Duration: 5
WSJF = (8 + 13 + 8) / 5 = 5.8

Kano Model
Customer Delight
Categorize features by customer satisfaction impact
How it works
Survey users with functional/dysfunctional questions
Categorize: Must-be → Performance → Attractive → Indifferent → Reverse

Use when

  • Understanding what customers actually value
  • Differentiating "table stakes" from "delighters"
  • Balancing feature investment across types

Avoid when

  • Need a quick rank-order for sprint planning
  • Can't run customer surveys
  • Pure B2B with <10 customers
Example categories

Must-be: Page loads in <3s (expected, no delight)
Performance: More integrations = more satisfied (linear)
Attractive: AI-powered suggestions (unexpected delight)

Value vs Effort
Visual / Workshop
2×2 matrix: plot features by value and effort
How it works
Plot on a 2×2 grid:
High Value + Low Effort = Quick Wins (do first)
High Value + High Effort = Big Bets (plan carefully)
Low Value + Low Effort = Fill-ins (if time allows)
Low Value + High Effort = Money Pit (don't do)

Use when

  • Workshop / whiteboard session
  • Non-technical stakeholders in the room
  • Need visual, intuitive output

Avoid when

  • Need precise rank-ordering
  • Too many items cluster in same quadrant
  • Effort estimates are unreliable
Example

Quick Win: Fix broken search filter (1 day, high impact)
Big Bet: Rebuild permissions system (6 weeks, enables enterprise)
Money Pit: Redesign settings page (3 weeks, no one cares)
